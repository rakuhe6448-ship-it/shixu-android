# 时序 · 原生安卓智能排期与提醒

Kotlin / Jetpack Compose / Room。Android 8.0（API 26）及以上，无开发者服务器。手动排期、提醒、桌面组件和备份均可离线使用。

[下载 1.2.0 APK](https://github.com/rakuhe6448-ship-it/shixu-android/releases/download/v1.2.0/ShiXu-1.2.0-debug.apk) · [查看发布版本](https://github.com/rakuhe6448-ship-it/shixu-android/releases)

## 打开与构建

用 Android Studio 打开本目录，安装 Android SDK Platform 35 与 Build Tools 35.0.0，使用 JDK 17 或更高版本、Gradle Wrapper 8.11.1。Android Studio 会创建本机的 `local.properties`；不要将别人的 SDK 路径直接复制到另一台电脑。

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug assembleDebugAndroidTest
```

Windows 路径含中文时，可使用 `scripts/build.ps1`。它会临时映射空闲盘符，优先使用 `.tools/android-sdk`，识别 Windows 已启用的 HTTP 代理，结束后恢复环境。标准项目不依赖本机 `.tools`：Android Studio 或普通 Wrapper 使用各自配置的 SDK 即可。

APK 的标准输出位置为 `app/build/outputs/apk/debug/app-debug.apk`。这是 Android 调试签名的可安装测试包。正式上架时，使用自己的长期签名密钥生成 release 包；项目不包含发布密钥、API Key 或开发者后端。

交付包位于 `releases/`：`ShiXu-1.2.0-debug.apk`、`ShiXu-1.2.0-source.zip` 和 `SHA256SUMS.txt`。将 APK 传到 Android 8.0 及以上手机，使用文件管理器打开安装；系统询问时为该文件管理器允许安装应用。首次进入先显示通知和精确提醒权限引导，返回系统设置后自动检查；也可明确选择“暂时只用排期”，以后在设置中重新检查。需要 AI 时，再填写自己的服务地址、模型和 Key。安装包不预填示例任务。

## 功能与使用

- **排期**：月历中的连续彩色横条表示跨日期事项，`◇` 表示只有截止日期。每周按不相交区间分行，超过三行可展开。选择日期查看当天事项，逾期入口会持续保留尚未完成的任务。
- **手动管理**：新建、编辑、删除、完成、重新打开；可设置开始日、截止日、截止时间、分类、颜色、备注及多个独立提醒。无日期事项保留在待办列表中。
- **重复事项**：支持每日、每周、每月、每年。完成当前一期后生成下一期独立任务，已完成的一期仍保留。月历显示已保存的当前事项，不预先生成无限未来实例。提醒本身也可独立设置重复规则。
- **提醒**：截止与提醒分别保存。手动编辑时可添加任意时间，或使用“截止前一天 09:00”。勾选“随截止时间一起移动”的提醒会跟随延期；明确的绝对时间保持原样。AI 未指定提醒时，程序尝试使用前一天 09:00，已过去的默认时间不会被擅自改到别的时刻。
- **已完成**：完成后从月历移除，进入待办页的“已完成”，取消尚未触发的相关提醒，并给出鼓励反馈。
- **AI 聊天**：文字、最多四张图片、系统分享入口、连续补充、引用消息、操作预览卡片、关联任务卡片。所有 AI 增删改完成操作均需在卡片中确认，确认后才写入 Room。手动任务也可在详情中选择“在 AI 对话中继续修改”。
- **多轮草稿**：未确认的事项独立保存在 Room 草稿中，不触发提醒。无引用的补充优先沿用最近明确讨论的事项；引用不同历史消息也会读取同一草稿的最新内容。提醒使用追加、修改、删除的增量操作，未变提醒保留 ID 与送达状态。聊天顶部可重新打开或取消待确认草稿；旧卡片过期后不能执行。
- **默认提醒替换**：新版本能区分自动默认提醒与用户指定提醒。首次明确配置提醒时替换尚未触发的自动默认建议，卡片显示删除内容；旧版本来源不明的提醒会保留，需用户明确修改。升级保留正式事项和提醒，旧版未确认卡片需要重新解析。
- **开始日期与类别**：AI 判断作业、复习、项目等是否需要持续安排。缺少开始日期且建议持续安排时弹出选项：今天开始、指定开始日期、仅设截止日期；全部选择后才可保存。开始日期按日设置，不改变独立的提醒时刻。单次会议、明确只设截止日的任务、已有开始日及普通延期不重复询问。类别优先遵循用户指定，否则按内容选学习、工作、生活或日常，支持之后手动修改。
- **图片**：模型支持图片时可直接发送；关闭图片模式时使用随包提供的中文 OCR，再发送识别文字。图片请求被服务以 400/415/422 拒绝且 OCR 有结果时，最多进行一次文本回退。
- **桌面组件**：长按系统桌面 → 小组件 → 时序，选择“今日”“近日”或“月历”。月历允许缩窄至 140dp、缩高至 260dp，具体网格限制由桌面决定；按宽高调整标题、日期、彩条及待办排版，窄长组件允许待办两行显示。Android 12 及以上适配桌面提供的多个尺寸，旧系统使用当前方向的可用尺寸。主题与透明度跟随应用设置；本地任务变化后刷新，点击日期或事项打开对应内容。
- **风格与主题**：系统/浅色/深色主题、自定义十六进制主题色与背景色、组件透明度；标准助手、御前小管家、宠物猫、沉稳管家、自定义聊天人格。常规通知全部使用本地模板，不在触发时调用 API。自定义人格的通知回退为标准模板。
- **备份**：系统文件选择器导入导出 JSON，包含任务、提醒、消息、聊天图片、关联、变更历史和外观设置。单份备份最多 50 MB，图片总计最多 30 MB。恢复替换现有数据，因此界面会再次确认。恢复保留本机 API 地址、模型配置和 Key，外部备份不能把现有 Key 重定向到其他服务；待确认的旧 AI 操作失效。

## API 配置

在“设置 → AI 连接”选择服务类型。“OpenAI 兼容”默认地址为空，可连接自选的兼容服务；只有“DeepSeek”预设填入 `https://api.deepseek.com/v1`。两类服务分别保存地址、模型和加密 Key，切换时不会把另一服务的 Key 自动带过去。修改后需要点“保存设置”。旧版本的服务配置与 Key 会迁移到对应类型。

填写地址和 Key 并离开输入框后，应用自动请求该服务的 `/models`，可搜索和选择返回的模型；也可手动刷新或填写模型名。服务不提供列表时会显示手动填写提示。列表仅表示服务公布的模型，不保证都支持聊天或图片。连接测试会发送一个极短聊天请求。基础地址需要包含服务要求的 `/v1` 等前缀，也支持完整 `/chat/completions` 地址。

模型不支持 `response_format` 时可关闭“请求 JSON 输出”，程序仍校验返回 JSON。未配置 Key 不影响其余功能。401、403、404、429、5xx、DNS、超时、证书和代理问题均有明确反馈。只有 429/503 最多自动重试一次；连接中断或超时不自动重发，避免重复计费。HTTPS 证书校验保持启用，跨地址重定向被拒绝以防 Key 泄露。

Key 使用 Android Keystore 的 AES-GCM 密钥加密后保存于应用私有存储，不进入数据库、日志或备份。聊天图片保存在应用私有目录。用户点击发送后，所选模型服务会接收本次输入及必要的相关上下文；应用不持续监听通知、不扫描其他应用、不监控日常行为。

## 提醒可靠性及平台边界

请在提醒页开启通知权限和精确闹钟权限。未获精确闹钟权限时使用系统普通闹钟，并明确标为“可能延迟”。应用通过开机、系统时间/时区变更、更新、进入前台、每次数据修改及 WorkManager 恢复任务重新安排提醒。

日期和时间按**设备当前时区的本地墙上时间**保存；更换时区后按新时区同一钟点重排。一次性错过的提醒补发一次。已有登记但尚未送达的重复提醒保留待送达实例；补发后跳到下一个未来实例，不补发所有历史周期。月末重复按原始锚点计算，避免 1 月 31 日经 2 月后漂移到 3 月 28 日。

Android 强行停止应用后不会继续运行它的闹钟和开机恢复代码，必须再次打开。部分 vivo 等厂商系统还需允许自启动、后台高耗电运行及通知。应用提供对应设置入口与状态提示，不能绕过系统禁令。无手机连接时，不能把模拟器结果当作 vivo 实机后台验证。
