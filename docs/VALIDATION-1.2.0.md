# 时序 1.2.0：多轮草稿改造验收

日期：2026-10-27。原生 Android 调试签名测试版，Room schema 2。

## 本轮实现

- 草稿和消息贡献关联持久化；正式任务仍是提醒调度的数据源。
- 无引用补充沿用最近明确交互；引用 A、B 或操作卡片读取同一对象的最新累计内容。
- 提醒追加、指定修改/删除、明确清空/替换；未变提醒保留 ID，保存时合并最新送达状态。
- 草稿版本、任务版本、来源消息幂等、过期卡片失效，以及失败事务后的冲突标记。
- 默认提醒来源区分；首次明确设置提醒替换已知 AUTO 建议，UNKNOWN 旧数据保留。
- 开始日期确认、待补充草稿、草稿重新预览/取消、v1/v2 JSON 备份与 Room 1→2 迁移。

设备首次执行 20 项，19 项通过，1 项因测试夹具假定每张旧表都有 indices 字段而失败，未进入迁移；修正夹具后单独执行迁移用例通过。没有为此重跑已通过的全套设备用例。后续新增“先给标题、后补截止时间”默认提醒分支，由新增单测验证。

测试包含 A→B→C→D 的三种确认时机：最后统一确认、A 先确认、逐轮确认。均验证同一正式任务、五条完整提醒、未变提醒 ID 保留，以及 A/B/C/D 消息关联。还覆盖数据库重开后找回草稿、迟到响应拒绝、手动修改冲突、已触发提醒不重新启用、源消息重复接收、取消后的新话题、追问不误绑定、备份恢复后重新确认，以及真实 AlarmManager 广播到达。

开始日期只执行一条实际 Compose 确认保存流程；本轮没有重复所有主题、小组件尺寸或 OCR 测试。最后的打包回归只检查关键草稿链路和开始日期确认。

## 实测边界

AI 操作链路使用固定、合法的结构化模型响应验证实际程序行为，未使用私人 API Key 进行付费调用；这些结果不代表任意 BYOK 模型都能准确理解自然语言。日期与目标结构校验、用户确认和版本保护仍由程序执行。

没有新增厂商实体手机测试。旧版来源不明的提醒不会被猜测为自动默认提醒；旧版待确认建议需要重新解析。绝对提醒沿用独立本地时刻语义，修改事项后不会自动变成新的“日期随事项移动、钟点固定”规则。
